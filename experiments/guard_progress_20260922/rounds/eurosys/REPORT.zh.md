# 本轮完成内容

以 `guard` 当前实现为准，重跑了 392 组 ns-3 实验，检查了总计 10,985,517 条流完成记录。每个主要比较使用 301–305 五个匹配种子。没有沿用旧稿的性能数值，也没有删去出现丢包或结果不利的运行。

保留的旧实验类型包括：共享链路拥塞、两发送端接收端汇聚、混合拥塞、OFLM 开关、四流动态公平性、16 主机 DP2 桶交换、16 主机 All-to-All，以及 128 主机 AliStorage 在 30%/50% 负载下的均值、P95、P99、P99.9 分组 slowdown。另保留 WebSearch、FbHdp2015 和 ring 压力测试，补充了四发送端汇聚和组件消融。详细对应关系见 `audit/experiment_coverage.md`。

基线现在包含 HPCC、Homa、DCQCN 和 TIMELY。主方案使用源码当前默认参数，包括 lambda=1.8、beta=0.125 和 gamma=1；没有为每项负载另选一个有利的 GUARD 参数。Homa 的数据队列与恢复机制以及 TIMELY 的默认 RTT 阈值在论文中明确说明。

全文按 MIT EECS CommKit 的问题、设计选择、实验论据与结论关系重写，并通过独立的可读性、论证连贯性和数据逻辑审阅。数值结果全部用图展示。论文 PDF 共 12 页（含参考文献），补充材料 3 页。

## 新结果如何改变论文结论

- 四个随机负载点上，GUARD 相对 HPCC 的平均 FCT 下降 16.2%–28.4%。
- 相对 Homa，30% 存储负载下平均 FCT 下降约 1.20%，50% 存储负载基本持平；WebSearch 和 analytics 分别增加约 10.62% 和 5.99%。
- 50% 存储负载下，完整 OFLM 相对同时关闭两项机制，使平均 FCT 下降 10.94%、grant 消息下降 86.31%，平均逐流速率提高 1.91%。
- 当前默认 GUARD 在 ring 压力测试中发生大量丢包，平均通信轨迹跨度约 124.98 ms；HPCC 和 Homa 约为 12.25 ms 和 12.19 ms。该结果已保留在论文中。

因此，论文保留随机负载和 OFLM 的实测收益，同时撤去“普遍优于所有方案”“稳定近零队列”“全面加速 AI 训练”等新数据不支持的概括。DP2/ring 采用开环通信轨迹，不能据此声称测得训练 JCT。100 us 的发送速率采样也不能支持旧稿的 8 us 收敛说法。

## 数据和复现

`manifest.json` 固定源码版本、可执行文件、输入和实验配置。`claim_evidence.json` 将每个论文数值映射到种子及原始运行；`raw/` 保存全部压缩原始输出，`raw_index.json` 提供哈希。`scripts/` 可重新生成分析、图和 PDF；英文 `README.md` 说明命令和指标定义。

原始 Conext 与 EuroSys 项目 ZIP 保存在 `backups/`。本轮没有修改 `guard` 的算法源码。证据仓库在本目录建立独立 Git 历史，避免把大型实验数据混入算法源码仓库。

参考写作指南：https://mitcommlab.mit.edu/eecs/use-the-commkit/
